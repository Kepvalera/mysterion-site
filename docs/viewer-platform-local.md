# MYSTERION: локальная платформа участников

Разработка только в `viewer-auth`. Ничего не опубликовано, удалённые базы и Access не изменялись. Включение новой системы требует явного `VIEWER_PLATFORM_ENABLED=true`. При отсутствии флага прежняя авторизация и административный интерфейс продолжают работать. `MEDIA_PAID_ENABLED` остаётся `false`.

## Что реализовано

- Существующая viewer-auth: регистрация, подтверждение email, вход, восстановление пароля, одна серверная сессия, выход и отзыв всех сессий. Argon2id и ограничения попыток сохранены.
- Редактируемые имя и фамилия; email и хеш пароля этим API изменить невозможно.
- Кабинет RU/EN: главная, курсы, видео, покупки, профиль. Реальные записи из D1, сроки доступа, пустые состояния. Чужие материалы и данные не возвращаются. Отдельных паролей для платформы нет.
- Продолжение обучения по сохранённым урокам, явная отметка завершения. API поддерживает сохранение позиции; автоматическое чтение таймкода сторонних iframe и автоматическая перемотка пока не подключены.
- Курсы, потоки, уроки, текстовые материалы. Школа допускает только потоки 3, 4, 5, 6. Номера — структура, реальные программы/уроки не выдуманы и не заполнены.
- Каталог `/catalog.html`: публичные опубликованные материалы, поиск, категории, заявки на покупку. Бесплатные YouTube/VK воспроизводятся без регистрации. Для VK нужна действительная ссылка `src` из предоставленного сервисом кода встраивания, а не произвольно составленный URL.
- Покупатель создаёт заявку по ID товара; название, цена, валюта и статус определяются сервером. Участник переводит свою заявку в «на проверке». Только владелец подтверждает фактическую оплату с конечным сроком доступа. Подтверждение и создание права — одна транзакция D1, повторное/конкурентное подтверждение не создаёт второе право.
- Ручные права на курс или видео, отзыв и истечение срока. Доступ к курсу включает новые опубликованные уроки в пределах срока. Закрытые уроки не публикуются в кабинет без действующего права. Старые Access-покупки не присваиваются новым viewer-аккаунтам по email.
- Единая русская админка `/admin-media.html`: обзор, видеотека, участники, курсы/уроки/тексты, заявки на оплату, доступы, сотрудники, сведения о настройке. Владелец может отключить подтверждённого участника, завершив его сессию, или изменить имя; неподтверждённый email так активировать нельзя.
- Обложки JPEG/PNG/WebP до 512 КиБ с проверкой сигнатуры. HTML/SVG не принимаются.
- Прямой TUS-клиент Bunny: файлы MP4/MOV/WebM, чанки 8 МиБ, реальный прогресс, пауза, HEAD-проверка смещения, обновление краткоживущего разрешения. Для восстановления после перезагрузки администратор повторно выбирает тот же файл: URL загрузки и отпечаток хранятся в защищённой D1, подписи — только в памяти. Файл не попадает в GitHub или D1. Страница должна оставаться открытой во время передачи; фоновая загрузка после закрытия мобильного браузера не обещается.
- Для нового черновика первый запрос состояния возобновления возвращает пустое состояние; затем сервер создаёт Bunny-видео, сохраняет его GUID и Library ID в D1 и выдаёт TUS-разрешение. Сохранение URL возобновления доступно только после этой привязки.
- При подключённом Bunny одна кнопка сохраняет черновик, получает разрешение, отправляет файл, опрашивает обработку и публикует только готовый разрешённый материал. Для загрузчика кнопка сохраняет только черновик. Без настройки Bunny операция выдаёт явную ошибку и сохраняет форму; успешная отправка не имитируется.
- Первичное сохранение видео использует стабильный UUID формы: повтор после потери ответа не создаёт вторую запись D1 и не перезаписывает изменённый материал. Неопределённый сетевой ответ непосредственно при создании ресурса у провайдера всё ещё может требовать сверки в Bunny; абсолютная идемпотентность внешнего API не обещается.
- «Убрать из каталога» — owner-only мягкое удаление: видео скрывается из каталога и библиотек участников, D1-запись помечается `deleted`, Bunny-файл, покупки и права сохраняются. Состояние `deleted` делает связанные права недействительными без удаления записей доступа.
- «Удалить полностью» — отдельное owner-only действие для привязанного Bunny-видео: после двойного подтверждения запись сначала скрывается и помечается ожидающей очистки, затем файл удаляется из привязанной библиотеки Bunny. Пока Bunny не подтвердил удаление, API возвращает ошибку, а запись остаётся видимой владельцу для повтора; после успеха D1-запись, покупки и права остаются сохранёнными, но недействующими.

## Права сотрудников

| Роль | Серверные возможности |
| --- | --- |
| Владелец | Каталог, участники, курсы, материалы, оплаты, права, сотрудники |
| Публикатор | Создавать и редактировать видео, загружать, публиковать бесплатные разрешённые материалы |
| Загрузчик | Только свои черновики и их загрузка; не публикация и не чужие записи |
| Участник | Собственный профиль, заявки, прогресс, действующие разрешённые материалы |

Сотрудники определяются по проверенному `sub` административного Cloudflare Access JWT и активной записи `platform_staff`. Email и роль из запроса/JWT не назначают полномочий. Проверяются подпись, issuer, audience и срок JWT. Права в браузере только скрывают лишние кнопки; каждый API повторно проверяет их на сервере.

Первый владелец **не создан**. API назначения сотрудников требует уже действующего владельца и не может создать первого. При включённом новом флаге старые `/api/media/admin/*` возвращают `use_platform_admin_api`, чтобы прежняя роль не обходила новые ограничения. При выключенном флаге старые API работают как прежде. Access-политики не менялись.

## Миграции

1. `0006_viewer_profile.sql`: добавляет имя/фамилию, сохраняет существующие ID, пароли и сессии.
2. `0007_participant_platform.sql`: добавляет VK и `created_by` в видео, таблицы `platform_staff`, `school_streams`, `platform_courses`, `platform_lessons`, `platform_materials`, `viewer_orders`, `viewer_grants`, `platform_progress`, `platform_uploads`, `platform_audit`.

`0007` требует схемы `0001`–`0006`. Перестройка `videos` проверена на заполненной SQLite с внешними ключами и на локальном D1/workerd. Старые RU/EN/DE значения видео сохраняются при перестройке и редактировании RU/EN. В интерфейсе DE нет. Миграции нельзя применять повторно вручную без проверки журнала.

В viewer-staging ранее были только таблицы `0004`/`0005`. Не следует сразу запускать «все миграции»: сначала сверить реальную схему и журнал. Если медийных таблиц нет, отдельно согласовать применение `0001`, затем `0002`, `0003`, и только после этого `0006`, `0007`, не запуская повторно `0004`/`0005`. Существующие тестовые данные должны сохраниться. В текущей работе ничего удалённо не применялось.

## Локальные команды

Из корня проекта, Node 24 (если `node` не доступен, использовать локальный `output/audit-tools/node-v24.22.2-win-x64/node.exe`):

```powershell
node tools/test-platform-migrations.mjs
node --import ./tools/register-viewer-wasm.mjs tools/test-platform.mjs
node tools/test-platform-runtime.mjs
node --import ./tools/register-viewer-wasm.mjs tools/check-platform-browser.mjs

node tools/test-bunny-upload.mjs
node tools/test-viewer-pages-build.mjs

```

Новые тесты используют временную SQLite или локальный workerd/D1, не облачный binding. Учетные записи, роли и материалы в тестах — изолированные fixtures, не реальные записи служения. Bunny API подменён локальным ответом. Настоящие библиотека, видео, письма и деньги не используются. Пример `wrangler.viewer-platform-local.example.jsonc` содержит нулевой UUID и не предназначен для удалённых команд. Существующий `wrangler.viewer-staging-d1.jsonc` не изменён.

## Что ещё требует внешней проверки

- Действительная загрузка/обработка Bunny, CORS/TUS, доступность YouTube/VK/Bunny из России и международных сетей. Локальные имитации не доказывают доступность провайдера.
- Доставка email и настоящая проверка в Safari/iPhone. Выполнена эмуляция мобильных размеров в Chrome, а не тест физического iPhone.
- Argon2id имеет прежние параметры `m=19456 KiB,t=2,p=1`. Замена интерфейса не устраняет известный риск превышения CPU Cloudflare Free при хешировании. Новые чтения каталога, сессий, подтверждение токена и управление материалами Argon2id не вычисляют. Тариф не менялся; снижение стойкости не применялось.
- Краткоживущий embed-токен ограничен также сроком права и сессии. Это не обеспечивает немедленный обрыв уже начатого HLS-потока. Более строгая защита активного платного потока — обязательный отдельный этап **до** включения платного просмотра.
- Платные ресурсы, платёжный шлюз, реквизиты карт не подключались. Каталог/заявки/ручные права можно локально тестировать, но платное видео остаётся закрытым флагом.
- Большие списки ограничены 200 записями (уроки/тексты — 500); полноценная пагинация, выгрузки и поиск участников по всей базе — следующий этап перед большим каталогом.

## План будущего развёртывания только staging

Ни один из следующих пунктов пока не выполняется автоматически:

1. После отдельного разрешения зафиксировать текущую ветку `viewer-auth`; проверить diff и секреты. Не отправлять в main.
2. Зафиксировать текущую схему/журнал и резервную копию **только** `mysterion-viewer-auth-staging` (UUID `99255496-6173-4efe-8b14-5924f3c1ceeb`). Сверить D1 binding тестового Pages-проекта; исключить `mysterion-media-staging`.
3. Согласовать и применить только недостающие миграции в порядке выше. При ошибке остановиться. Проверить `PRAGMA foreign_key_check` и неизменность старых аккаунтов/сессий.
4. Отдельно подтвердить первичного владельца по реальному `sub`, полученному после проверки JWT существующим доверенным процессом Access. Не брать email или непроверенные поля браузера. Подготовить точный SQL с этим `sub` для просмотра владельцем, а не выполнять шаблон.

   Концептуальный SQL, **не готовая команда для выполнения**:

   ```sql
   INSERT INTO platform_staff(access_sub,role,active,created_at,updated_at)
   SELECT '<CONFIRMED_VERIFIED_ACCESS_SUB>','owner',1,unixepoch(),unixepoch()
   WHERE NOT EXISTS (SELECT 1 FROM platform_staff);
   ```

5. Только по отдельному разрешению настроить staging `VIEWER_PLATFORM_ENABLED=true`, существующую viewer-auth, точный `MEDIA_PUBLIC_ORIGIN` тестового проекта, `MEDIA_DB` тестовой базы, Access issuer/AUD. `MEDIA_PAID_ENABLED=false`, Bunny отключён, пока отдельно не разрешено подключение существующей библиотеки. Секреты вводятся исключительно в Cloudflare, не в репозиторий/чат.
6. Существующую Admin Only политику не менять автоматически. Защиту `/api/platform/admin/*` необходимо отдельно согласовать в Access; сервер проверяет JWT даже без edge-правила. Для публикатора/загрузчика дополнительно потребуется явно разрешённый вход в Access — сама роль D1 не обходит Admin Only.
7. После разрешённого staging deployment проверить реальными отдельными аккаунтами вход/выход, восстановление, права сотрудников, регистрацию заявок, подтверждение/отзыв/истечение, CORS загрузки и CPU. Платный просмотр не включать.
8. Production/main, рабочая D1 и существующие секреты остаются вне этого плана.
