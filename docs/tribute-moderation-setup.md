# Модерация Tribute Shop

## Webhook

Адрес: `https://mysterion-international.com/api/tribute/webhook`.

Обработчик принимает только POST JSON и проверяет `trbt-signature` как HMAC-SHA256 от **исходных байтов** тела с Production Secret `TRIBUTE_API_KEY`. Документация задаёт алгоритм, но не уточняет текстовую кодировку: принимаются только полный 32-байтовый digest в hex или каноническом base64. Неверная подпись — 401, неверное тело — 400, неподдерживаемый метод — 405, отсутствие Secret — 503.

Проверяются поля официального конверта `name`, `created_at`, `sent_at`, `payload`. Содержимое уведомления не возвращается и не логируется. Максимальный размер тела — 64 КиБ. Для webhook не нужна браузерная сессия или Origin-заголовок; проверяется фактический разрешённый адрес запроса, а не forwarded-заголовки.

Это этап **проверки и подтверждения получения**, а не обработки оплат: валидное уведомление получает `200 {"status":"ok"}`. Платежи, заказы и права не создаются, не обновляются и не сохраняются. Поэтому повторное уведомление безопасно и не продлевает доступ. До будущей автоматической выдачи потребуется отдельный журнал платежей и идемпотентная транзакция. На текущем этапе webhook не хранит историю уведомлений для будущей выдачи.

В Tribute укажите этот адрес в настройке Webhook URL магазина. Не закрывайте **этот точный webhook-путь** интерактивным Cloudflare Access: подлинность проверяется подписью. Защита существующего `/api/platform/admin/*` остаётся прежней.

Официальные источники: [Shop Webhooks](https://wiki.tribute.tg/for-shops/api/webhooks), [OpenAPI Tribute Shop](https://tribute.tg/api/v1/openapi/shop/en).

## Аккаунт участника для модерации

Сначала владелец подтверждает отдельный email под своим контролем и точные ID существующих демонстрационных материалов. Не использовать основной аккаунт владельца, не назначать роли Cloudflare Access, `users` или `platform_staff`.

Инструмент `tools/create-tribute-moderation-account.mjs` работает только с `MEDIA_DB`, фактически привязанной к Production проекта `mysterion-international`. По умолчанию он выполняет лишь SELECT-проверки:

```powershell
& ./output/audit-tools/node-v24.22.2-win-x64/node.exe --import ./tools/register-viewer-wasm.mjs tools/create-tribute-moderation-account.mjs --email <отдельный-контролируемый-email> --demo-videos <подтверждённые-UUID-через-запятую>
```

После проверки добавить `--execute`. Создаётся **новый** viewer-аккаунт; существующий аккаунт с этим email инструмент не меняет. Первоначальный случайный пароль хешируется штатным Argon2id и сразу отбрасывается: его нет в файлах, аргументах команды, GitHub или журнале. Аккаунт активируется по подтверждению владельцем контроля email; для назначения известного пароля используется существующее восстановление по этому адресу. В таблицы административных ролей инструмент не пишет.

Выдаются только прямые права на указанные опубликованные бесплатные демонстрационные видеозаписи, на 7 дней, без покупок и прав на настоящие платные курсы. Чужие аккаунты и права не меняются. При частичной ошибке новый аккаунт отключается; receipt в игнорируемом `output/` содержит только ID и результат, без пароля. Общедоступные материалы сайта остаются доступными как любому посетителю.

### Создание и передача временного пароля

1. Открыть `https://mysterion-international.com/viewer-account` → «Забыли пароль?» и указать подтверждённый email аккаунта модерации.
2. Владелец открывает полученное письмо и задаёт уникальный временный пароль через существующую форму; сохранить его в менеджере паролей. Не присылать пароль, reset-ссылку или токены в чат разработки.
3. Передать модератору адрес входа, email и пароль через адресованную ему одноразовую ссылку менеджера паролей со сроком, например 24 часа. Ссылку восстановления не передавать: она позволяет менять пароль.
4. После модерации в существующей админке отключить **этого** участника — это завершит его сессию. Демо-права истекут через 7 дней, но автоматического отключения самого аккаунта нет. Продлевать или повторно использовать его без решения владельца не следует.

Письма отправляются только штатной формой восстановления, по явному действию владельца. Новый почтовый сервис и новый механизм авторизации не добавляются.
