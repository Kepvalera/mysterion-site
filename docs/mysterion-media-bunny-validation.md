# Проверка перехода на Bunny Stream

Дата: 2026-11-08. Сравнение с основой 9432718.

## Дополнительная проверка готовности домена

После сохранённой Bunny-интеграции 92084d9: **126 серверных**, **5 сценариев TUS-клиента**, **67 браузерных проверок** прошли. Паттерн-проверка исходников не нашла секретов/отслеживаемых credential-файлов; это не замена provider secret scanning. Миграции production и ресурсы не запускались.

Дополнительно выполнены локальная компиляция Pages Functions и штатная валидация маршрутов через Wrangler 4.158.0 (pages functions build / optimize-routes), без deploy и облачных ресурсов. Исправлен конфликт include-правил: точные /admin-media/ и /media-login/ убраны, поскольку уже покрываются соответствующими /*. tools/check-media-routes.mjs проверяет ограничения Pages, отсутствие пересечений, защищённость вариантов URL и сохранение статических маршрутов; серверный набор содержит регрессионную проверку этого конфликта.

После live-проверки URL-кодированного алиаса обнаружена отдача статического административного шаблона вне middleware. Исправлено архитектурно: полный UI возвращается из серверного шаблона только после JWT/роли; статические HTML заменены закрытым fallback без формы/управляющего скрипта. Набор проверяет оба отказа и разрешённый случай с настоящим серверным шаблоном, а также отсутствие формы в обоих публичных файлах. Пересборка Functions и Chrome-проверка Bunny-интерфейса после переноса прошли.

Новые проверки: канонический домен принимается, pages.dev/preview/www/неверный порт отклоняются даже с валидным JWT и поддельными Host/Origin/Forwarded. Административный HTML не отдаётся anonymous/viewer/disabled/поддельному JWT и на альтернативном домене. Проверены варианты .html/без расширения/со слешем, запрет вложенных путей и сохранение статического redirect. В Chrome реальный middleware с пустой конфигурацией возвращает 503 и не передаёт форму: RU/EN/DE, 375/390/430/1440, без переполнения и ошибок JS. Скриншоты protected-admin-390.png и protected-admin-1440.png сохранены в output/media-check.

Проверки ниже описывают предыдущий этап и остаются частью набора. Реальные Access-политики домена, DNS/TLS и поведение маршрутизации Cloudflare нужно проверить после ручного подключения; локальные тесты этого не подменяют.

## Выполнено локально

- **75 серверных проверок** — tools/test-media.mjs. SQLite в памяти, заполненная база до миграции 0002, сохранность видео/покупок/прав/аудита и foreign_key_check. JWT подписываются реальными временными RSA-ключами процесса. Внешние API заменены локальными ответами.
- Проверены роли, Origin, поддельные/неверные JWT, разные Admin/Viewer AUD, неподготовленная конфигурация, создание/привязка Bunny GUID, идемпотентный повтор разрешения загрузки, аренда/конфликт версий, готовность перед публикацией, sync/обложки/предпросмотр, tombstone и повтор удаления.
- Подписи TUS/embed и CDN HMAC независимо сверены через Node crypto. Секреты не входят в ответы. Бесплатный каталог работает без R2.
- Платный доступ: нет права/покупки, чужой владелец покупки, refund, revoked, expired, некорректная дата, disabled, неверный AUD, флаг выключен — отказ. Разрешённый случай получает TTL до 180 секунд. Старые GET/stream маршруты платный файл не открывают.
- **5 сценариев TUS-клиента** — tools/test-bunny-upload.mjs: 17 МиБ тремя частями; пауза; продолжение через HEAD с подтверждённого смещения; обновление истёкшего разрешения; блокировка внешнего URL и пауза до начала передачи. Ни одного реального upload.
- **43 браузерные проверки** — tools/check-media-browser.mjs, Chrome headless, 375/390/430/1440, RU/EN/DE, CSP из _headers, закрытая панель, видимая форма, отсутствие переполнения/ошибок JS. Тестовый файл 9 МиБ прошёл два PATCH, прогресс достиг 100%. Проверены освобождение iframe при закрытии, ссылка реального защищённого входа после отказа и публичный подписанный Bunny iframe после разрешения.

Скриншоты/результаты — output/media-check, исключены из Git/публикации. Все записи помечены TEST ONLY и существуют только в тестах, не в production-каталоге. Тестовые ключи генерируются в памяти, а не записываются в исходники.

## Что не проверено и не выполнено

- Реальные Cloudflare Access/D1 bindings, политика доменов, Bunny Library/CORS/обработка/CDN и длинный урок требуют staging и настроек владельца.
- Реальный Safari/iPhone/Android не проверены; Chrome mobile viewport не выдаётся за тест этих устройств.
- Платные ресурсы не создавались, production-миграции не выполнялись, платежи не подключались, production-права не выдавались.
- До push текущий production /api/media/videos возвращал 503: инфраструктура ещё закрыта. Новый код не включает её автоматически.
- Нагрузка живой передачи/кодирования и поведение длительной playback-сессии не измерялись. Локальные ответы API не заменяют такую проверку.

Для запуска нужны Node 24+ и локальный Chrome; браузерный скрипт использует puppeteer-core из существующего каталога output/audit-tools/lighthouse. Эти инструменты не являются клиентскими зависимостями сайта. Следующие действия владельца описаны в [инструкции](mysterion-media-owner-setup.md).
