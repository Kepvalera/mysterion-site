# Режим сайта MYSTERION

Режим меняет серверное отображение и маршрутизацию, а не исходные страницы.
Миграция 0016 добавляет одну таблицу site_display_settings с режимом main,
без паузы продаж, без подтверждения НПД. После публикации временный режим
не активируется автоматически. Существующие таблицы и данные не перезаписываются.

## Управление владельцем

Откройте `/admin-media` → **Настройки → Режим сайта**.
Кнопка **Включить временную страницу** требует подтверждения. Публичные страницы,
включая прямые URL и RU/EN-пути, начинают показывать отдельную страницу услуг.
Переключение применяется при следующем запросе без деплоя; HTML не кешируется.
Админка, авторизация, API, webhook и просмотр приобретённого через
`/viewer-account.html` сохраняются. Публичные каталоги скрыты на сервере.

Кнопка **Восстановить MYSTERION** возвращает исходные HTML, меню и страницы.
Покупки, сроки, записи, файлы, сопоставления и настройки Tribute остаются прежними.

Пауза новых покупок независима от digital_public_sales.enabled. Временный режим
устанавливает дополнительный purchases_paused=1. Восстановление main её не снимает.
После восстановления владелец может отдельно подтвердить **Возобновить публичные
продажи** (или **Снять паузу временного режима**, если основной переключатель
выключен). Применится сохранённый глобальный флаг; сам флаг не меняется.
До этого новые ссылки оплаты и checkout блокируются сервером. Уже открытая
страница внешнего Tribute может завершить оплату; подписанные уведомления и
возвраты продолжают обрабатываться без изменения действующих правил выдачи.

В настройках есть **Данные временной страницы — заполнить владельцу**:
параметры консультаций, условия услуг, оплаты/возврата, обработки данных,
контакты и подтверждение действующего статуса НПД. RU/EN редактируются отдельно.
Пустые поля показывают явные сообщения об уточнении. НПД не заявляется до
подтверждения владельцем после проверки статуса. Известная цена школы — 30 000 ₽,
обучение — 3 месяца, записи — ещё 6 месяцев после окончания. Платёжных кнопок
на временной странице нет. Это не подключение ЮKassa/Prodamus и не готовые
юридические документы: недостающие сведения должен подтвердить исполнитель.

Изменения режима и содержания фиксируются в существующей sales_operations;
последние время и проверенный Access sub владельца показаны в настройках.
Обычный пользователь или сотрудник без роли owner менять режим не может.

## Аварийное восстановление без админки

Войдите владельцем аккаунта Cloudflare → D1 → привязанная к Pages база MEDIA_DB
→ Console. Выполните только:

```sql
UPDATE site_display_settings
SET mode='main', purchases_paused=1, revision=revision+1,
    updated_at=unixepoch(), updated_by='emergency:cloudflare-owner'
WHERE id=1;
```

Перезагрузите сайт. Вернётся основной MYSTERION, новые продажи останутся на паузе.
Данные услуг, НПД и глобальный переключатель продаж сохранятся. Для снятия паузы
после восстановления используйте обычную защищённую кнопку владельца.

Если проблема в самом коде, предыдущий рабочий коммит:
`1487c7e19eb1d206a10eb9ba14ea179fc7c59834`. Существующий Production-деплой этого
коммита можно выбрать в Cloudflare Pages → Deployments → Rollback. ВАЖНО:
старая версия не знает о purchases_paused. Перед откатом кода отдельно выключите
публичные продажи существующей кнопкой либо, только как аварийное действие
владельца, установите digital_public_sales.enabled=0 через D1. Не откатывайте
базу целиком ради изменения режима. Новая добавочная таблица старому коду не мешает.

## Резервная копия перед внедрением

Локальная закрытая папка:
`C:\Projects\mysterion-site\output\site-mode-backup-20261115\`.
Файлы: `production-before-site-mode.sql`, `backup.json`, `restore-check.json`.
Папка доступна текущему пользователю Windows и SYSTEM, исключена из публикации.
Полный дамп содержит данные пользователей: не загружайте его в GitHub и
не отправляйте открытой ссылкой. Скопируйте его в собственное защищённое хранилище.
Локальная проверка восстановила дамп в SQLite и сверила количество строк во
всех 43 таблицах; foreign_key_check — без нарушений.

При необходимости полного аварийного восстановления данных используйте экспорт
только после отдельной оценки новых покупок/изменений после даты копии. Импорт
старого дампа поверх действующей D1 не является обычным способом восстановления
сайта и не должен выполняться автоматически.
