# MYSTERION MEDIA: кабинеты, коллекции и ручной доступ

Это инструкция по подключению, а не подтверждение работы в production. `/media-test` не нужен и не создан. Администратор работает через `/admin-media.html`, зритель — через `/media-login.html`, каталог — `/media.html`.

## Что добавлено

- Cloudflare Access остаётся единственным способом входа. Пароли на сайте не создаются и не хранятся. Подпись JWT, issuer, AUD, срок действия и активная роль проверяются сервером.
- Администратор добавляет зрителя по **Subject ID из проверенного Access-входа**. Новый зритель видит свой идентификатор в кабинете и передаёт его администратору. Это идентификатор, не токен. Перед добавлением администратор сверяет личность с подтверждённым обращением/оплатой. Произвольная роль через форму не назначается; создаётся только viewer.
- Ручной доступ выдаётся к конкретной записи до обязательной даты, с основанием. Выдача/продление/отзыв и блокировка аккаунта журналируются. `purchases` не пополняется фиктивными платежами. Старые действительные покупки/entitlements продолжают работать.
- Коллекции содержат до 20 записей, имеют RU/EN/DE и состояния «скрыта/опубликована». Публичный фильтр показывает опубликованные коллекции. Добавление видео в коллекцию **не выдаёт доступ к нему**; права проверяются отдельно на каждое видео. Публикация коллекции не публикует её черновые видео.
- Кнопка подключения существующего Bunny Video ID работает только для пустого черновика, только у admin. Сервер проверяет видео через API своей библиотеки; произвольный embed URL не принимается.
- Ручные обложки: при существующем `MEDIA_BUCKET` сохраняется прежний механизм; без R2 используется D1, PNG/JPEG/WebP до 512 КиБ. Большую обложку заранее оптимизируйте. Видео в D1 не сохраняются.
- Загруженный файл, обработка, предпросмотр, публикация/скрытие и удаление используют существующую Bunny-интеграцию. Закрытие вкладки не сохраняет TUS resume URL. Ограничение интерфейса — 20 ГБ, это не серверная квота Bunny.

## 1. Миграция — только после выбора базы

`0001_media.sql` и `0002_bunny_stream.sql` не изменены. Новая `0003_media_members.sql` создаёт **collections, collection_videos, manual_grants, membership_audit, media_covers**. Она не удаляет существующие данные и не выдаёт прав.

Все три миграции проверяются в локальном D1 скриптом `tools/test-media-staging.mjs`. Удалённые миграции этой задачей не выполняются.

После отдельного решения владельца применить новую миграцию к staging сначала проверьте историю:

```powershell
npx wrangler@4.158.0 d1 migrations list mysterion-media-staging --remote --config wrangler.staging.jsonc
```

Ожидается: 0001/0002 уже применены, pending только 0003. Если 0001/0002 выполнялись вручную через SQL Console и не зарегистрированы в `d1_migrations`, остановитесь: сначала нужно согласовать историю, не запускайте CREATE TABLE повторно.

Когда база и история подтверждены:

```powershell
npx wrangler@4.158.0 d1 migrations apply mysterion-media-staging --remote --config wrangler.staging.jsonc
npx wrangler@4.158.0 d1 execute mysterion-media-staging --remote --config wrangler.staging.jsonc --file tools/check-media-staging.sql
```

Точная staging-база: `d4966184-ae55-46cf-bf74-4dff1e7debdd`. Не связывайте её с production-сайтом без отдельного решения. Для production отдельно согласуйте базу, backup и миграцию. Не копируйте `wrangler.production.example.jsonc` в активную конфигурацию вслепую.

## 2. Cloudflare Pages / Access

Следуйте основной [инструкции владельцу](mysterion-media-owner-setup.md) для `MEDIA_DB`, issuer и секретов. Дополнительный флаг **MEDIA_MEMBERS_ENABLED=true** задаётся только в окружении, где уже проверена 0003. По умолчанию он выключен. Без него существующий каталог и Bunny CRUD не требуют новых таблиц.

В одном **Admin Access application** объедините `/admin-media`, `/admin-media.html`, `/admin-media/*`, `/api/media/admin/*`, с одинаковым Admin AUD и Allow только для конкретных администраторов (желательно MFA).

В отдельном **Viewer Access application** объедините `/media-login`, `/media-login.html`, `/media-login/*`, `/api/media/view/*`, с другим Viewer AUD. Выберите реальный IdP или Cloudflare email OTP и политику разрешённых зрителей; не используйте Bypass. Вход через Access не равен выдаче материалов. Subject ID сверяется с записью D1.

Сохраняйте `MEDIA_PUBLIC_ORIGIN` равным **текущему фактически подключённому HTTPS-origin**, без слеша. Новый mysterion-international.com пока не активируется. Если точные Access rules невозможно подключить к текущему pages.dev, нужен реальный подключённый домен; код не заменяет внешний Access-вход обходным паролем. API и HTML отвергают альтернативные origin; static fallback не содержит управляющей формы. Не распространяйте рабочие production secrets/bindings на preview.

## 3. Реальная проверка Bunny перед платным просмотром

`MEDIA_PAID_ENABLED` оставьте **false**. Не отключайте embed/CDN token authentication. Библиотеку и секреты настройте по основной инструкции; ключи вводятся только как Pages encrypted secrets, не в чат/Git.

1. В существующей админ-панели сохраните черновик Bunny. Подключите согласованный тестовый GUID из своей библиотеки либо загрузите MP4/MOV/WebM. Проверяйте прогресс, обновление статуса, обработку, обложку, название и предпросмотр. Не публикуйте тестовую запись как реальный материал служения.
2. Проверьте неподписанный iframe, просроченный signed embed URL, прямой MP4/original/HLS playlist и сегменты. Они должны быть недоступны без предусмотренной защиты. Подпись плеера **не является DRM**. Доступность файлов зависит от настоящих настроек Bunny; локальный mock этого не доказывает.
3. На согласованном изолированном окружении проверьте Viewer Access, добавление зрителя, выдачу/отзыв/истечение ручного доступа, блокировку пользователя, отсутствие доступа у другого зрителя. Для сквозной проверки платной записи требуется отдельное решение владельца о временном включении платного playback именно в проверяемом окружении. Код сам флаг не включает.
4. Подписанный URL выдаётся на 180 секунд после серверной проверки. После отзыва новое разрешение не выдаётся; уже выданный URL и начатый Bunny-сеанс не отзываются мгновенно. Проверьте длинный урок и поведение после окончания URL. При инциденте ограничивайте доступ также в Bunny.
5. Проверьте воспроизведение из России на готовой `/media.html` и в кабинете, а также настоящий iPhone Safari. Эмуляция Chrome не заменяет эти проверки.

Только после успешной реальной проверки и отдельного решения владельца можно включать платный просмотр. Реального платёжного шлюза и автоматической регистрации с паролями здесь нет: вход делегирован Access, выдача разрешений — администратору.
