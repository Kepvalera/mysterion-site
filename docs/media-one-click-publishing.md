# MYSTERION MEDIA — загрузка и публикация одной кнопкой

## Работа администратора

1. В существующей `/admin-media.html` нажмите «Новый материал».
2. Заполните названия RU/EN/DE и описания, выберите MP4/MOV/WebM, категорию, обложку и доступ.
3. Нажмите **«Загрузить и опубликовать»**. Основная форма не требует Bunny Video ID, выбора статуса или отдельной синхронизации.
4. Оставьте вкладку открытой. Система сохраняет черновик и обложку в существующей архитектуре, получает серверное разрешение TUS, отправляет файл напрямую в Bunny частями по 8 МиБ, показывает фактический процент, проверяет обработку и публикует готовый материал.

«Сохранить черновик» сохраняет метаданные/выбранную обложку, но не начинает передачу видео и не публикует его. Выбранный видеофайл не сбрасывается ни при таком сохранении, ни при промежуточных шагах. Отдельные кнопки Bunny, импорт существующего Video ID, источник, год и дата оставлены в дополнительных настройках.

При бесплатном доступе стоимость и валюта скрыты; при смене на бесплатный цена становится нулевой. Для платного материала основная кнопка заблокирована при MEDIA_PAID_ENABLED=false. Сервер независимо применяет тот же запрет.

## Реализация и защита

- Используются прежние Pages Functions + D1 + Bunny Stream, без нового видеохостинга и без новых миграций.
- Администратор по-прежнему подтверждается Access JWT и активной ролью D1. Все изменяющие API проверяют Origin; editor не может публиковать, загружать или перезапускать Bunny-видео.
- Новый POST `/api/media/admin/videos/:id/publish` принимает только revision. Он проверяет сохранённый материал, платный флаг, привязку библиотеки, GUID, фактический статус Bunny 4 и отсутствие конкурирующей операции. Меняется только статус/дата публикации/ревизия, а действие попадает в аудит. Тексты не перезаписываются этой операцией.
- Publication date при использовании основной кнопки — фактический момент готовности и публикации. Это не планировщик отложенной публикации.
- Проценты загрузки приходят из XHR upload progress; после завершения передачи отдельно показывается прогресс обработки Bunny. Опрос — раз в 10 секунд, с остановкой в скрытой вкладке и продолжением при возвращении.
- Запрос подписи и создание Bunny GUID выполняются на сервере. Секретные ключи не передаются браузеру; клиент получает прежнее краткоживущее разрешение TUS. Подписанное воспроизведение и защита платного просмотра не менялись.
- Повтор публикации уже опубликованной записи безопасен; изменение revision во время операции даёт конфликт. Сервер не доверяет клиентскому сообщению «готово».

## Ошибки и продолжение

- Ошибка сети при загрузке оставляет черновик, форму, выбранный файл и TUS-сессию в памяти. Повтор основной кнопки продолжает отправку через HEAD/подтверждённый offset; начальное сохранение не сбрасывает FileList.
- Если загрузка закончена, а публикация не подтвердилась, повтор использует готовую запись и не отправляет файл повторно. При потерянном ответе проверьте текущий статус материала: сетевой сбой после запроса публикации не доказывает, что сервер не успел её выполнить.
- При подтверждённой ошибке обработки Bunny (статус 5/8) повтор основной кнопки с выбранным файлом создаёт новую Bunny-запись для **того же черновика**, сохраняя тексты/категорию/обложку. Старый неудачный GUID сохраняется в audit_log (`bunny_retry_from:...`); старый файл автоматически не удаляется. Его очистку в Bunny при необходимости выполняет администратор после проверки, чтобы не удалить исходный материал.
- «Остановить и оставить черновик» прекращает автоматическое ожидание/передачу и не запускает публикацию. Во время самого серверного запроса публикации остановка недоступна.
- Обложки без существующего R2 — PNG/JPEG/WebP до 512 КиБ (существующее хранение D1); с R2 сохраняется прежний лимит 2 МиБ. Для слишком большой обложки показано отдельное сообщение.
- Пауза/возобновление TUS и автоматическое ожидание привязаны к открытой вкладке. После её перезагрузки/закрытия файл и URL продолжения не сохраняются в localStorage. Готовое/обрабатываемое видео можно открыть из списка и продолжить публикацию; для незавершённой загрузки файл потребуется выбрать снова. Автопубликация не обещается после закрытия вкладки: фонового задания/очереди в этом изменении нет.

## Проверено локально

- **201 серверный тест**: прежние JWT/cookie/role/Origin проверки, новая публикация только готового Bunny-видео и его воспроизведение, неверная ревизия, лишние поля, editor/anonymous, запрет платной публикации, контролируемый retry и аудит.
- **78 браузерных проверок Chrome**: RU/EN/DE, ширины 375/390/430/1440; реальная форма и FileList, изолированные ответы API/Bunny/TUS; загрузка 9 МиБ двумя PATCH, обработка → публикация, обложка, ошибка PATCH → повтор без второго черновика, черновик без загрузки, сохранение файла, платная кнопка, ошибка публикации → повтор без отправки видео, отмена обработки.
- **5 тестов TUS-клиента**: размер частей, подтверждённый HEAD offset, возобновление, обновление истёкшей подписи, запрет стороннего Location.
- Локальная сборка Pages Functions, проверка синтаксиса и паттерн-проверка секретов.

Файлы: admin-media.js, bunny-upload.js, media-i18n.js, media.css, media-worker/src/page-templates.mjs, media-worker/src/worker.mjs, tools/test-media.mjs, tools/check-media-browser.mjs и этот документ. Главная, фотоархивы, миграции, Access policies, реальные записи D1 и MEDIA_PAID_ENABLED этой задачей не менялись.

## Реальная проверка владельцем после deployment

В своей Access-сессии загрузите согласованный реальный небольшой бесплатный файл через основную кнопку. Проверьте настоящее CORS/TUS-разрешение Bunny, процент, обработку, обложку, появление в `/media.html`, воспроизведение и повтор после отключения сети. Затем проверьте большой MP4/MOV/WebM и настоящий iPhone Safari. Локальные API-моки не подтверждают кодеки, скорость сети, настройки CORS и реальные статусы конкретной библиотеки. Тестовые fixtures этой задачей в Bunny или публичный каталог не загружались.

Источники: [Bunny Get Video](https://bunny.net/docs/api-reference/stream/manage-videos/get-video), [Bunny TUS](https://bunny.net/docs/stream/tus-resumable-uploads).
