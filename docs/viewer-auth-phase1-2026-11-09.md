# Аккаунты зрителей — локальный этап 1

Не опубликовано. Удалённая D1, существующие users/права, Access Admin Only, административные API и Bunny не изменялись. MEDIA_PAID_ENABLED не включался. Автоматического переноса аккаунтов нет.

## Реализация

Независимая viewer_accounts: email, Argon2id, подтверждение почты, статус, версия авторизации, RU/EN. Регистрация, повтор письма, вход, выход, отзыв всех сессий, восстановление пароля. Email приводится к нижнему регистру; точки и +суффиксы сохраняются. Первый этап поддерживает обычные ASCII email. Пароль не обрезается/не нормализуется: 15–128 Unicode-символов, максимум 512 байт UTF-8.

Одна строка viewer_sessions на аккаунт. Новый вход атомарно заменяет токен; неверный пароль не отзывает сессию. Перед сохранением повторно проверяется версия учётных данных: конкурентный сброс пароля делает старый вход недействительным. Сессии читаются непосредственно из D1 primary, без кеша/реплик. Cookie __Host-mysterion_viewer: Secure/HttpOnly/SameSite=Lax/Path=/, без Domain. В D1 только SHA-256 случайного 256-битного токена. Абсолютный срок 7 дней, неактивность 12 часов, запись last_seen не чаще раза в 5 минут. Вкладки одного профиля делят сессию.

Одноразовые email-токены хранятся хешированными; повтор запрещён атомарным consumption_id. При подтверждении вводится исходный пароль: нельзя незаметно подтвердить чужую предварительную регистрацию. Восстановление через собственную почту позволяет заменить неизвестный пароль и отозвать сессии. Подтверждение действует 24 часа, сброс 30 минут. Повторная отправка инвалидирует предыдущую ссылку того же назначения.

Origin/Sec-Fetch-Site, обязательный XMLHttpRequest-заголовок и JSON защищают изменяющие запросы от CSRF. Сторонний CORS не включён. Тело ограничено 4 КиБ. D1 rate limits по IP/email, идентификаторы HMAC с отдельным секретом. Проверка/сброс по токену также ограничены по аккаунту. Истёкшие buckets очищаются порциями. Ответы регистрации и восстановления одинаковы для известных/неизвестных email; неизвестный login проходит фиктивный KDF. Письма отправляются через waitUntil, forgot/resend имеют минимальное время ответа 500 мс. Это снижает риск перечисления, но не доказывает полную неразличимость таймингов.

## Хеширование

@noble/hashes 2.0.1 закреплён в media-worker/vendor/noble-hashes; MIT LICENSE и npm SHA-512 provenance сохранены. Только нужное дерево исходников, без install scripts. Argon2id v19: m=19456 КиБ, t=2, p=1, соль 16 байт, результат 32 байта. Формат версионирован, параметры строго проверяются до KDF. Один KDF на isolate, не более трёх заданий с очередью. Доступные буферы очищаются; JavaScript-строки гарантированно обнулить невозможно. Библиотека не загружается в браузер.

В настоящем локальном workerd шесть KDF заняли около 2,5 секунд wall time. Это НЕ production CPU-замер и не доказательство соответствия тарифу Free. Параметры нельзя уменьшать ради лимита тарифа: до включения нужно измерить CPU/память под нагрузкой на согласованной инфраструктуре.

## Маршруты и интерфейс

- GET /api/viewer/session — собственная минимальная сессия без email/admin-роли.
- POST /api/viewer/register, /login, /verify-email, /resend-verification.
- POST /api/viewer/forgot-password, /reset-password, /logout, /logout-all.
- /viewer-account.html — публичные формы RU/EN. Токен письма во fragment, сразу убирается из адресной строки и хранится в памяти вкладки. GET ссылки ничего не расходует. Пароль очищается после отправки формы.

Шапка предпочитает прежнюю Access-сессию администратора. При её отсутствии новая система проверяется отдельно; когда модуль выключен, прежнее поведение сохраняется. Включённый модуль направляет зрителей в viewer-account.html; viewer logout не вызывает Access logout. Парольная сессия не принимается административными API. Старый media-login и Access viewer API пока сохранены. Новый кабинет показывает подтверждённый вход, но права/покупки/Bunny к нему ещё не подключены: следующий этап. Платный просмотр остаётся выключенным.

## Миграции

0004_viewer_accounts.sql создаёт только viewer_accounts. 0005_viewer_sessions.sql создаёт viewer_sessions, viewer_email_tokens, viewer_rate_limits, viewer_auth_events и индексы. Нет DROP/ALTER старых таблиц, links/переноса users или фиктивных покупок. Проверены SQLite с существующим admin и локальный D1 binding workerd. Удалённые staging/Production не использовались.

Пакеты курса/конференции и динамический доступ к новым опубликованным урокам будут следующим модулем, согласно согласованной архитектуре.

## Email: предложен Resend

Есть серверный адаптер официального HTTPS API, без SDK и без следования перенаправлениям. Нужны подтверждённый домен отправителя, SPF/DKIM/DMARC и ограниченный ключ отправки. Использовать чужой pages.dev как адрес отправителя нельзя. Аккаунт провайдера и домен не создавались, реальные письма не отправлялись. Ошибка доставки не раскрывает существование email, отображается общий ответ; можно повторить отправку. Надёжная очередь повторов — следующий инфраструктурный этап.

Настройки ниже нужны позже, только после согласования staging. Сейчас ничего задавать в Production не требуется:

| Имя | Тип | Значение |
|---|---|---|
| VIEWER_AUTH_ENABLED | Variable | По умолчанию false; true только на подготовленном staging |
| VIEWER_RATE_KEY | Secret | Независимое случайное значение >=32 символов для HMAC лимитов |
| VIEWER_EMAIL_PROVIDER | Variable | resend |
| RESEND_API_KEY | Secret | Ограниченный ключ отправки |
| VIEWER_EMAIL_FROM | Variable | Подтверждённый адрес отправителя |
| MEDIA_DB | D1 binding | Выбранная база после одобренных миграций |
| MEDIA_PUBLIC_ORIGIN | Variable | Точный origin, без завершающего / |
| MEDIA_PAID_ENABLED | Variable | false |

Не передавать ключи в чат/Git. wrangler.viewer-local.example.jsonc — неактивный локальный пример. Сейчас безопаснее запускать тесты с приватным in-memory mailer: endpoint чтения писем/токенов не добавлен. Не выполнять --remote или миграции Production. Настройка реального staging — следующий согласованный шаг с резервной копией и проверкой binding.

- tools/test-viewer-auth.mjs: 67 проверок — RFC 9106 vector, соль/пароли, отсутствие открытых токенов, email verification, CSRF/лишние поля/размер, конкурентные входы/ссылки, гонка reset/login, logout-all, idle/absolute expiry, disabled, лимиты, закрытый Admin API. Существующий admin неизменён.
